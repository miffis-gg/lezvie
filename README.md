# Лезвие — концепт городского барбершопа

[Сайт на GitHub Pages](https://miffis-gg.github.io/lezvie/) · [Репозиторий](https://github.com/miffis-gg/lezvie)

Полный одностраничный сайт для портфолио: React 18, Vite, строгий TypeScript и CSS Modules. Проект реализует утверждённые PRODUCT.md, DESIGN.md и STRUCTURE.md. Визуальная система сохранена: графитовые поля, тёплый светлый прайс, оранжевые действия, локальные Roboto Condensed и Golos Text. Фотография отделена от HTML-интерфейса.

## Запуск

Нужен Node.js 22+ и npm. В папке проекта:

```sh
npm ci
npm run dev
```

Открыть адрес, который напечатает Vite (обычно http://127.0.0.1:5173/).

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`dist/` — готовая статическая сборка. Двойной клик по index.html через `file://` не заменяет HTTP-сервер, поскольку приложение использует ES-модули.

## Что реализовано

- Все секции по STRUCTURE.md, мобильное меню и контекстная нижняя кнопка записи.
- Восемь услуг с фильтрами, четыре демонстрационных профиля, шесть работ с фильтрами и доступным lightbox.
- Первый визит, три пакета, правила сервиса, восемь независимых FAQ, контакты с честной картой-заглушкой.
- Общий сценарий записи из hero, прайса, профиля или пакета. Совместимость услуги и мастера, семь дат, занятые и пустые слоты, вычисляемые цена и длительность.
- Обратимые шаги, нативные radio-поля, видимый фокус, удержание фокуса в диалогах, Escape, skip-link, reduced motion.
- Валидация имени, нормализованного телефона, комментария и согласия. Локальная обработка 750 ms, защита от двойного submit, подтверждение и полный сброс.

Все данные вымышлены. Форма не выполняет запросов, не использует cookies или браузерные хранилища. Введённые контакты существуют только в оперативной памяти компонента, очищаются после подтверждения и исчезают при обновлении страницы. Нет backend, внешних API, карт или аналитики. На сайте нет настоящих отзывов, рейтингов и контактов.

У пакета «Регулярный визит» итог 6 600 ₽ за три визита, время 60 минут относится к первому визиту; оставшиеся визиты не бронируются автоматически. Оплаты нет.

## Файлы

- `src/app/` — сборка страницы и связь секций со сценарием записи.
- `src/components/` — header, hero, каталог, редакционные секции, контакты и виджет.
- `src/data/content.ts` — типизированные данные и генерация демонстрационных дат относительно локального календаря устройства.
- `src/types/content.ts` — модели.
- `src/hooks/useBooking.ts`, `src/lib/booking.ts` — состояние, пересчёт совместимости и валидация.
- `src/styles/` — reset, токены и локальные шрифты; компоненты используют CSS Modules.
- `public/images/`, `public/fonts/` — локальные ассеты, доступные без сторонних запросов.
- `ASSETS.md` — происхождение и точные промпты всех 12 созданных фотографий, лицензии шрифтов и иконок.
- `tests/booking.test.ts` — граничные значения и совместимость записи.
- `scripts/browser-qa.mjs` — воспроизводимая проверка четырёх ширин и интерактивных сценариев в Edge, включая axe.
- `scripts/lighthouse.mjs` — мобильный Lighthouse для production preview.

## Проверка в браузере

Для автоматизированной проверки нужен установленный Microsoft Edge. Сначала запустить dev-сервер, затем в другом терминале:

```sh
node scripts/browser-qa.mjs
```

Можно задать `QA_URL`, чтобы проверить production preview. Скриншоты сохраняются в `.impeccable/review`, отчёты — в `test-results` (обе папки исключены из Git). Скрипт проверяет 390, 768, 1280 и 1440 px, отсутствие overflow, загрузку изображений и шрифтов, фильтры, lightbox, FAQ, совместимость мастеров, занятые/пустые слоты, ошибочные и корректные данные, успех/сброс, меню и ввод с клавиатуры. Он также проверяет отсутствие сторонних запросов, cookies и браузерного сохранения данных. Отдельный `node scripts/zoom-qa.mjs` проверяет настоящий масштаб браузера 200% в собственном временном профиле Edge внутри `tmp/`, не меняя пользовательский профиль. По умолчанию этот скрипт и Lighthouse используют адрес http://127.0.0.1:4173/lezvie/; для обычного preview задать `QA_URL=http://127.0.0.1:4173/`.

При проверке сборки с `VITE_BASE_PATH=/lezvie/` запускать preview с тем же значением `VITE_BASE_PATH`; адрес будет http://127.0.0.1:4173/lezvie/. При обычной сборке без переменной достаточно `npm run preview`.

Итоговые результаты и границы проверки — в [QA.md](QA.md).

## GitHub Pages

GitHub Pages настроен на https://miffis-gg.github.io/lezvie/. Workflow `.github/workflows/pages.yml` запускается **только вручную** через Actions → Build and deploy GitHub Pages → Run workflow. Автоматической публикации при push нет.

1. Загрузить обновления в `main` вместе с актуальным package-lock.json.
2. В Actions выбрать Build and deploy GitHub Pages и вручную запустить workflow.
3. Дождаться успешного завершения. Workflow выполняет установку, TypeScript, тесты, сборку и Pages deploy. В Settings → Pages уже выбран Source: GitHub Actions.

Workflow передаёт `VITE_BASE_PATH=/<имя-репозитория>/`. Для пользовательского репозитория `<username>.github.io` или собственного домена заменить его на `/`. Для локальной сборки по умолчанию используется `./`.

При необходимости base можно задать в `.env.local`:

```ini
VITE_BASE_PATH=/lezvie/
```

Без маршрутизатора: URL содержит только якоря, обновление опубликованного адреса не требует серверных перенаправлений. В index.html указаны canonical и абсолютные `og:url` / `og:image` для опубликованного адреса. При переносе на другой домен обновить их. LocalBusiness schema с вымышленными контактами не используется.

## Skills и ассеты

Применены `impeccable` (контекст, утверждённая визуальная система, craft floor, адаптация и финальная проверка), `imagegen` (встроенная генерация 12 фотографий), workflow `sites` для локальной реализации без регистрации/деплоя и `context-mode` для обработки выводов проверок. Пользовательские документы не заменялись. Оригиналы фотографий не нужны для сборки: все WebP уже находятся в репозитории. Вспомогательный `scripts/optimize-images.mjs` предназначен для локальной подготовки из исходников генерации и требует отсутствующий в репозитории `tmp/image-sources.json`.
